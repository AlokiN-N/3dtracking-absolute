# e04 — SAM 2 + подгонка 3D-модели грузовика (офлайн, упор в точность)

Точка выхода — **кабина тягача**: передний нижний край кабины по осевой (по модели `CargoTruck.fbx`).
Режим — офлайн (по условиям реальное время не требуется). Под Way1 ничего не подгонялось: масштаб модели
найден по самим видео, параметры сглаживания — из физики.

## Результат на Way1 (1001 кадр, 5 камер)

| версия | RMSE | MAE | медиана | p95 | макс. | покрытие |
|---|---|---|---|---|---|---|
| e03 (YOLO + вычитание фона, онлайн) | 10.6 м | 9.1 м | 8.3 м | 22.2 м | — | 96% |
| **e04 v3** (`run.sh`) | **4.14 м** | **2.51 м** | **1.61 м** | 12.2 м | 15.7 м | 100% |
| e04 final (`FINAL=1 run.sh`) | 3.46 м | 2.31 м | 1.73 м | 10.3 м | 12.5 м | 100% |

- В v3 на кадрах 300–700 (грузовик видят 2–4 камеры) MAE 0.98 м, медиана 0.90 м — меньше метра.
- Основная ошибка — участки, где грузовик видит одна дальняя камера (кадры 150–300 и 930–1000, дальность 340–510 м).
- Метрики: `metrics_way1_v3.json`, `metrics_way1_final.json`.

## Конвейер

1. **Подсказки** (`stage0_detect.py`, `stage1.py`). Сначала YOLO11n и вычитание фона дают грубую 3D-траекторию (e03). По ней в каждой камере выбирается рамка-подсказка.
2. **Маски SAM 2.1** (hiera-small, ONNX; `stage2_sam.py`):
   - рамка-подсказка, обрезка вокруг объекта, кадр масштабируется до 1024;
   - если маска упирается в край рамки, рамка дорасширяется;
   - маски, растёкшиеся по фону, отбраковываются.
3. **3D-модель** `CargoTruck.fbx` (`fbxlib.py` → выпуклые оболочки частей в `truck_hulls.json`, `model.py`):
   - части модели: кабина, рама тягача, колёса, кузов-прицеп, шасси прицепа;
   - масштаб ×3.1 найден самокалибровкой по кадрам с ≥3 камерами (`scale_test.py`), без истины.
4. **Подгонка позы по всем камерам сразу** (`fit.py`, `fit_all.py`):
   - x, y, z, курс и тангаж подбираются так, чтобы силуэт модели совпал с масками;
   - **две части**: маска SAM может покрыть весь грузовик или только кузов / только кабину — берётся лучшая интерпретация («не видим кузов — работаем с тем, что видно»);
   - мера сходства устойчива к перекрытию: маска должна лежать внутри силуэта, а часть модели за деревом или холмом штрафуется слабо;
   - камера-выброс (ложная маска) отбрасывается.
5. **SAM 2 по проекции подогнанной модели** (`stage2b_sam.py`) — для камер, где маски не было или она не совпала с моделью. Затем повторная подгонка.
6. **Глобальное сглаживание** (`gsmooth.py`):
   - вся траектория решается одной разреженной задачей наименьших квадратов (эквивалент RTS-сглаживателя);
   - точность каждой камеры анизотропная: поперёк луча — пиксели, вдоль луча — по размеру силуэта;
   - ускорение ограничено 0.5 g;
   - выбросы гасятся IRLS (функция Коши).
7. **Только final: одна камера** (`monofit.py`):
   - ориентация берётся из траектории;
   - глубина считается по *относительному* изменению размера силуэта;
   - коэффициент калибруется на кадрах до ухода второй камеры и после её появления.

## Запуск
```
pip install onnxruntime opencv-python numpy scipy pandas matplotlib
bash tools/get_yolo.sh                     # models/yolo/yolo11n.onnx
mkdir -p models/sam2 && cd models/sam2 && curl -LO https://huggingface.co/vietanhdev/segment-anything-2.1-onnx-models/resolve/main/sam2.1_hiera_small_20260221.zip && unzip sam2.1_hiera_small_20260221.zip && cd ../..
bash experiments/sam2_model/run.sh         # v3;  FINAL=1 ... — версия final
```
- Данные кладутся в `data/` или задаются через `PELENG_DATA`.
- Результат: `out/e04/trajectory.csv` (`Frame;Loc_X;Loc_Y;Loc_Z`, см) и `out/e04/report/` (видео + метрики, если есть истина).

## Скорость (2 ядра CPU, без GPU)

| этап | время |
|---|---|
| SAM 2.1-small | ~3.3 с на маску |
| SAM, каждый 4-й кадр (≈1100 масок) | ≈1 ч |
| подгонка модели | ≈25 мин |
| сглаживание | секунды |

На GPU SAM 2 работает ~30–50 мс на маску. Качество можно поднять масками на каждом кадре (`STRIDE=1`) — дольше пропорционально.
