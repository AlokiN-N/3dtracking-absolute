# Современные измерения и проверка качества

Основной запуск сохраняет покадровый режим с задержкой `k=0`. Новый конвейер принимает измерения выбранных модулей, проверяет их по геометрии и движению и передаёт подтверждённую позу в общее состояние.

## Подключённые модули

| Параметр | Что включается |
| --- | --- |
| `--pico-subpixel` | Непрерывные соответствия PicoPose с учётом центров ячеек обучающей сетки |
| `--gotrack-source PATH --gotrack-checkpoint PATH` | Сопоставление текущего RGB с видимой поверхностью CAD через GoTrack |
| `--roma-source PATH` | RoMa v2 для текущих изображений разных камер с проверкой по известной калибровке |
| `--tapnext-source PATH --tapnext-checkpoint PATH` | Последовательное сопровождение точек CAD через TAPNext |
| `--sam-video facebook/sam2.1-hiera-tiny` | SAM2 с отдельной потоковой памятью на каждую камеру |
| `--unified` | Текущее состояние SE(3), скорость и ковариация через GTSAM |
| `--renderer numpy` или `--renderer pytorch3d` | Растеризация видимой поверхности для GoTrack |
| `--sequential-models` | Выгрузка неактивных моделей в RAM между вызовами |
| `--unverified-measurements` | Исследовательский режим принятия геометрических кандидатов без проверки по движению |

Для GoTrack, RoMa и TAPNext требуется треугольная метрическая CAD-модель через `--target` или `--appearance-target`. При смене объекта задаются его собственные масштаб и точка отсчёта. Начальную область незнакомого объекта можно указать через `--seed-box`.

По умолчанию новый геометрический кандидат должен дополнительно подтверждаться движением в двух камерах. Подтверждённые камеры записываются в `measurement_cameras`, ошибка репроекции — в `reprojection_px`. Режим `--unified` обновляет внутренний прогноз по подтверждённым новым измерениям. При их отсутствии он сохраняет текущий результат основного трекера.

`position_std_m` содержит линейную оценку неопределённости выходной точки CAD по трём мировым осям. Она учитывает смещение этой точки относительно центра модели и неопределённость ориентации. Её калибровку оценивают на отдельном наборе сцен.

## Память и причинность

SAM2 получает только текущий кадр. Сессия хранит два последних подготовленных изображения и ограниченное окно численных признаков. TAPNext получает один кадр на вызов и переносит скрытое состояние. Пропуск камеры или смена разрешения сбрасывает её состояние сопровождения.

GoTrack и RoMa работают с текущими синхронными изображениями. Шаблоны создаются из CAD. Прежние выданные координаты остаются зафиксированными. Оранжевая траектория с настраиваемым лагом рассчитывается отдельно.

Субпиксельный режим учитывает соглашение обучающего кода PicoPose. Его непрерывные целевые координаты заданы от границы ячейки, а таблица пикселей — от её центра. Преобразование вычитает половину шага перед переходом в исходное изображение. Это проверяется отдельным тестом.

## Запуск на Linux

На сервере каталоги разделены по назначению. `app/` содержит исходники, `models/` — веса, `vendor/` — сторонний код, `runtime/` — окружения, `assets/` — CAD, `cache/` — кэши, `data/` — исходные видео и калибровки, `out/` — результаты экспериментов, `public/` — веб-демо. Прежние пути ресурсов сохранены через совместимые ссылки.

В `configs/linux-runtime.json` находятся каталоги дополнительных пакетов и кэша данного сервера. Для другого сервера создайте собственный файл `*.local.json`. Основное окружение Python загружается первым, чтобы сохранить согласованную пару ONNX Runtime и CUDA.

```bash
python tools/run_online.py --runtime configs/linux-runtime.json \
  --data /path/to/data --out /path/to/output \
  --target /path/to/target.json \
  --sam models/sam2/sam2.1_hiera_tiny \
  --gotrack-source /path/to/vendor/gotrack \
  --gotrack-checkpoint /path/to/gotrack_checkpoint.pt \
  --unified
```

Версии дополнительных Python-пакетов, проверенные на Linux, записываются в `requirements/modern-tested.txt`. PyTorch3D собирается под установленный PyTorch. Проверенный вариант использует CPU-растеризацию и нейросетевую обработку на GPU.

Ревизии внешних исходников и SHA-256 весов зафиксированы в `configs/models.lock.json`. Загрузчик размещает ресурсы в указанном каталоге данных.

```bash
python tools/fetch_models.py --root /path/to/linux-data
python tools/fetch_models.py --root /path/to/linux-data --verify-only
```

## Воспроизводимые эксперименты

`tools/experiment.py` создаёт отдельную копию исходников перед запуском. Он сохраняет команду, хеши исходников и чекпойнтов, ревизии внешних репозиториев, журнал и результаты. После обработки видео отдельная команда читает эталон и считает метрики.

```bash
python tools/experiment.py \
  --out /path/to/new-experiment \
  --runtime configs/linux-runtime.json \
  --data /path/to/data \
  --reference /path/to/reference.csv \
  --baseline /path/to/baseline/replay.json \
  -- --sam models/sam2/sam2.1_hiera_tiny
```

`comparison.json` содержит покадровые ухудшения, потерю покрытия и отдельный `release_passes`. Допуск требует снижения MSE и MAE, сохранения максимума и покрытия, отсутствия ухудшений на всех кадрах с эталоном и совпадения координат на кадрах без валидного эталона.

Эксперименты последовательно занимают GPU через общий файловый lock. Эталон, параметры вычислительного окружения и исходный результат копируются в каталог эксперимента. `tools/check_prefix.py --experiment PATH --limit 540` повторяет префикс из того же снимка исходников. `tools/promote.py` повторно проверяет метрики и атомарно меняет каталог опубликованного результата.

## Независимые CAD-сцены

Генератор BlenderProc использует отдельный рендерер. Он создаёт калибровки, метрическую CAD-модель, RGB-потоки и эталонные координаты. Поддерживаются процедурные формы и произвольный `--target`, движение камеры, изменение освещения, перекрытие и отключение камеры.

```bash
python tools/prepare_validation.py --out /path/to/new-scene \
  --frames 24 --shape assembly --seed 437 --blackout-camera 9 --occlusion
blenderproc run tools/render_validation.py /path/to/new-scene/scene.json \
  --blender-install-path /path/to/linux-data/blender
python tools/encode_validation.py /path/to/new-scene/scene.json
```

`seed.args` содержит начальные области выбора объекта. `reference.csv` используется только при отдельной оценке. Для проверки переносимости формы и случайные начальные условия оценочного набора следует сохранять независимо от набора настройки.

## Проверки

Тесты в `tests/` проверяют преобразование кропов, соглашение координат PicoPose, проекцию CAD, прежние пути импорта, обратную связь пяти- и шестимерной позы, совпадение префиксов состояния и сброс после потери объекта.

```bash
python -m unittest discover -s tests -v
```

Полные результаты экспериментов на сервере находятся в `/mnt/shared-data/peleng-hackathon/out/modernization`. Исследовательские результаты с покадровыми ухудшениями оцениваются отдельно от опубликованной траектории.
